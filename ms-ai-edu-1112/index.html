4. Q&A

Q1. Managed Apps(현 Copilot Managed Runtime)는 MS가 미리 만든 커넥터만 쓸 수 있는 것으로 아는데, 사용자 지정 커넥터나 REST API를 쓸 수 있게 하는 계획이 있나?

답변 미기록교육 노트에는 답변이 남아 있지 않습니다.

참고(이후 공개 문서로 확인한 내용): npm 라이브러리는 앱에 번들해서 쓸 수 있습니다. 기본 보안 정책(CSP)이 외부 CDN·외부 호출을 막고 허용 커넥터도 1st-party 일부로 제한되지만, 관리자가 허용 범위를 넓힐 수 있습니다. CMR은 Ignite 2026에서 GA되었습니다.

Q2. Agent Builder의 Agent Add 기능은 Power Platform(Copilot Studio)의 A2A와 같은 것인가? 서드파티 에이전트와 연결되나?

답변 미기록교육 노트에는 답변이 남아 있지 않습니다. 확인되는 대로 갱신 예정입니다.

참고: Copilot Studio의 연결된 에이전트는 A2A 에이전트 연결을 프리뷰로 지원합니다(Agent Builder와는 별개 기능).

Q3. Autopilot은 클라우드 영역만 담당해서 로컬 PC에서는 에이전트를 쓸 수 없다. 로컬 PC 쪽은 어떤 서비스가 맡나?

A. Windows의 Hybrid Intelligence (Cloud + Local AI)가 그 역할을 맡는 방향입니다. Scout(현 Autopilot)는 클라우드 에이전트로 정리되고, PC 관련 기능은 Hybrid Intelligence 쪽에서 이어집니다. 기술적 핵심 주제는 “OS 수준 격리”와 “로컬에서의 AI”입니다. 자세한 내용은 아래 5장을 참고하세요.

5. Windows Hybrid Intelligence = Cloud + Local AI

주제내용
무엇이 바뀌나
  • Copilot이 PC의 파일과 최근 활동에 접근하고, 파일 이동·설정 변경 같은 작업을 직접 수행
  • 작업 성격에 따라 PC의 로컬 AI 모델과 Cloud AI 중에서 선택. 비용이나 개인정보 보호가 중요하면 로컬 모델, 어려운 작업은 Cloud
  • Copilot이 ‘도우미(Assistant)’에서 실제로 일하는 ‘에이전트(Agent)’로 진화
발표 시연 예시에이전트가 이메일을 찾고 → 여러 위치의 세금 문서를 찾아 → 이름을 바꾸고 → 폴더에 정리하고 → ZIP으로 묶고 → 답장까지 준비
Local AI의 의미Privacy + Cost. 세금 문서 분류를 PC의 로컬 모델에서 처리해 세부 정보를 Cloud로 보내지 않음. 로컬 모델은 PC에서 추가 비용 없이 작업 수행
보안: Execution Containers (MXC)
  • PC 에이전트가 넓은 시스템 권한을 갖는 것 자체가 보안 문제 → Microsoft Execution Containers로 에이전트가 접근할 수 있는 파일과 네트워크 범위를 제한
  • MXC: 신뢰할 수 없는 코드나 동적으로 생성된 작업을 위한 정책 기반 실행 계층
  • 방향: 기본 거부 권한(default-deny), 에이전트별 ID(per-agent identity), OS 수준 격리
  • OpenAI Codex와 OpenClaw가 지원 중, Claude Code와 Perplexity도 지원 예정으로 소개됨
하드웨어: NVIDIA 협력‘PC = Personal AI Compute’로 확장. NVIDIA RTX Spark 기반 Windows PC에서 대형 AI 모델을 로컬로 실행하는 방향. Surface Laptop Ultra, Surface RTX Spark Dev Box와 Asus·Dell·HP·Lenovo·MSI 시스템이 소개됨. 하드웨어를 넘어 AI 소프트웨어까지 함께 설계하는 full-stack 파트너십

Ignite 2026 후속: MXC에 새 격리 기능이 추가됐고, Windows 365 for Agents가 Copilot Credits 과금 대상이 됐습니다. 자세한 내용은 대시보드의 Ignite 2026 결과 정리를 참고하세요.
