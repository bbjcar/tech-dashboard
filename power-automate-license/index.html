1. 두 제품은 무엇이 다른가?

이름은 둘 다 "Power Automate"지만, 일하는 방식과 실행되는 곳이 완전히 다른 두 제품입니다.

데스크톱 흐름 · RPA

PAD (Power Automate Desktop)

🤖 사람 대신 PC 화면을 조작하는 로봇
마우스 클릭, 키보드 입력, 화면 읽기를 녹화하고 그대로 반복합니다.
  • 설치: Windows용 앱 (Windows 11에는 기본 포함)
  • 실행 위치: 사용자의 PC나 서버 (켜져 있어야 함)
  • 대상: 엑셀, 사내 업무 프로그램, 웹사이트, 파일·폴더
  • 적합한 경우:
    • API로 연동할 수 없는 시스템을 자동화할 때
    • 시민 개발자가 UI로 동작하는 프로그램의 자동화를 코딩 없이 쉽게 만들 때
클라우드 흐름 · 커넥터/API

Power Automate (웹 기반 클라우드 흐름)

🔗 서비스와 서비스를 잇는 연결 통로
커넥터와 REST API로 클라우드 서비스끼리 데이터를 주고받습니다.
  • 만드는 곳: 웹 브라우저 (make.powerautomate.com)
  • 실행 위치: Microsoft 클라우드 (PC가 꺼져 있어도 실행)
  • 대상: Outlook, Teams, SharePoint, 외부 SaaS, REST API
  • 적합한 경우: 메일 수신, 정해진 시간 같은 이벤트로 시작되는 자동화

3. Premium · Process · Hosted Process 라이선스 비교

Premium은 사람(사용자)에게, Process와 Hosted Process는 자동화 대상(머신, 클라우드 흐름)에게 할당하는 라이선스입니다.

Process 계열은 Premium을 대체하지 않습니다
  • 무인 실행용 머신에 Process를 할당하려면, 그 머신을 Premium 사용자가 등록해야 합니다.
  • 클라우드 흐름에서 데스크톱 흐름을 실행할 때 사용하는 연결의 소유자에게 Premium이 필요합니다.
  • 따라서 무인 실행 구성은 Premium(개발자) + Process 또는 Hosted Process(실행 머신) 조합입니다.

  • 실행 PC를 Power Automate에 머신으로 등록해야 합니다.

5. 핵심 포인트 ② 기본 환경을 폐쇄한 조직에서 Premium이 필수인 이유

📌 전제(예시): 조직이 기본(Default) 환경을 논리적·기능적으로 폐쇄한 경우
따라서 자동화 개발은 개인 개발자 환경(관리형)에서 진행합니다.
  1. 라이선스 없는 PAD는 기본 환경에서만 쓸 수 있습니다.
    Windows에 포함된 무료 권한으로는 기본 환경에서 개인 생산성 용도로만 데스크톱 흐름을 만들 수 있고, 다른 환경에서는 만들 수 없습니다.
  2. 기본 환경을 폐쇄하면 무료로 쓸 수 있는 경로가 사라집니다.
    PAD와 클라우드 흐름 모두 기본 환경이 아닌 곳에서 개발해야 합니다.
  3. 관리형 환경에서는 모든 사용에 Premium 라이선스가 필요합니다.
    관리형 환경에서 클라우드 흐름을 실행하는 모든 사용자에게 Power Automate Premium 라이선스가 필요합니다. 표준 커넥터만 쓰는 흐름도 마찬가지입니다.
  4. 무료 개발자 플랜으로는 대체할 수 없습니다.
    개발자 플랜에는 관리형 환경에서 리소스를 실행할 권한이 없습니다. 비관리형 개발자 환경은 지원이 종료되며, 기존 개발자 환경은 2026년 12월 15일 전에 관리형으로 전환해야 합니다.
  5. 결론: 개발자 1인당 Power Automate Premium이 필요합니다.
    PAD 예약 실행이나 REST API 연동까지 고려하면, Premium은 선택 사항이 아니라 개발을 시작하기 위한 전제 조건입니다.
