1. 한눈에 보기

새로 만든 Copilot Studio 에이전트는 GUID 하나(A)가 Entra Agent ID · Teams 앱(매니페스트) ID · Bot ID · Copilot 에이전트 ID를 모두 겸합니다. 카탈로그 쪽 ID(Title ID, TAC App ID)만 따로 발급되고, 같은 에이전트가 링크 공유와 조직 카탈로그 두 갈래로 스토어에 올라갈 수 있습니다.

1 GUID = 4역할

신원 · 통신(Bot) · 배포(매니페스트) · Copilot 등록이 같은 값 실측

타이틀 2개

링크 공유(Shared)와 조직 카탈로그(LOB)가 별도 타이틀 · 별도 가용성 실측

통합 ≠ 기본값

MAC·TAC 통합 전에는 승인 상태가 따로 → 이중 승인 필요 실측

설치는 별도

통합 동기화 대상은 앱 상태·조직 설정·사용자 지정. 설치·고정은 TAC에서 따로 추정

2. Agent Map

왼쪽에서 오른쪽으로: 만드는 곳 → 신원 → 앱 패키지 → 카탈로그 → 사용자 화면. 주황색 A는 같은 GUID입니다. 아래 띠는 관리자 승인·설정 층입니다.

4. 매니페스트로 본 연결

Copilot Studio 채널(Teams 및 Microsoft 365 Copilot)에서 내려받은 매니페스트를 요약했습니다. 실제 값은 기호로 바꿨습니다.

{
  "id": "A",
  "bots": [{
    "botId": "A",
    "scopes": ["team", "personal", "groupChat", "copilot"],
    "registrationInfo": {
      "source": "microsoftCopilotStudio",
      "environment": "E",
      "schemaName": "new_<에이전트이름>"
    }
  }],
  "validDomains": ["*.botframework.com", "copilotstudio.microsoft.com", "…"],
  "authorization": { "permissions": { "resourceSpecific": [
    { "type": "Delegated", "name": "ChatMessage.Read.Chat" },
    { "type": "Delegated", "name": "ChannelMessage.Read.Group" }
  ]}},
  "copilotAgents": { "customEngineAgents": [{ "id": "A", "type": "bot" }] }
}

하나의 GUID

id, botId, customEngineAgents[].id가 모두 A = Entra Agent ID.

사용자 지정 엔진 에이전트

Copilot Studio 에이전트는 Microsoft 365 Copilot에 bot 유형 사용자 지정 엔진 에이전트로 등록됩니다. Agents Toolkit 선언형 에이전트(declarativeAgents)와 구분됩니다.

기본 RSC 권한

설치된 채팅·팀 채널 메시지 읽기 위임 권한이 기본 포함. 보안 검토 단골 질문입니다.

개발자 정보 기본값

개발자 이름·MPN ID·링크가 기본값으로 들어갑니다. 조직 제출 전 채널 → 세부 정보 편집 → 더 보기에서 채우세요.

5. 배포 경로 · Teams 조직 설정 2가지

TAC → Teams apps → Manage apps → Actions → Org-wide app settings → Custom apps의 두 토글입니다.

설정대상끄면근거
① Let users install and use available apps by default조직 카탈로그에 올라간 사용자 지정 앱의 기본 가용성. 개별로 사용자를 지정해 저장한 앱에는 적용되지 않음개별 지정하지 않은 사용자 지정 앱은 아무도 못 씀문서
② Let users interact with custom apps in preview카탈로그에 없는 미리 보기 앱: 사용자 업로드, CS 설치 링크 공유, Built with Power Platform. 업로드 기능의 조직 전체 스위치이기도 함사이드로드·링크 공유 설치 차단 (승인 제출은 가능)문서

6. 승인: MAC vs TAC · 통합 여부

구분MAC (Agents → Requests)TAC (Manage apps)
승인 동작Publish to store → 대상·정책 템플릿·권한 동의게시 상태 Submitted / 상태 Blocked → Publish → Published / Allowed
통합된 테넌트한쪽 승인으로 끝. 앱 상태·조직 설정·사용자 지정이 양쪽에 동기화 문서 — 테스트 테넌트에서 MAC 승인만으로 일정 시간 뒤 TAC 표시 확인 실측
통합되지 않은 테넌트승인 상태가 따로. MAC 승인 후에도 TAC는 "요청 대기"로 남아 이중 승인 필요 실측

사례 (고객 테넌트, 익명화)

  1. MAC에서 조직 카탈로그 제출을 승인 → 1주일이 지나도 TAC 목록에 없음
  2. Teams 스토어에서 검색은 되지만 추가하면 오류 (MAC은 게시, TAC는 차단 상태)
  3. Teams에서 공유 링크를 만들어 앱 ID를 확보 → TAC 앱 상세 주소에 직접 입력 → "요청 대기" 상태 확인
  4. TAC에서 다시 Publish → 반영 대기. 원인은 관리 센터 통합 전 상태로 판단

통합 여부 판단

방법판단 기준신뢰도
"Move to unified app management" 버튼TAC Manage apps 상단에 있으면 비통합. 공식 문서에 나온 유일한 확인 경로⭐⭐⭐ 문서
같은 앱 상태 비교TAC·MAC에서 허용/차단·가용성이 다르면 비통합⭐⭐⭐
조직 설정 비교TAC ①과 MAC "조직에서 만든 앱 설치 허용"이 다르면 비통합⭐⭐⭐
Popular apps 위젯통합 테넌트의 Manage apps에 표시 (사용량 없으면 안 나옴)⭐

설정을 한 번도 바꾸지 않은 테넌트는 자동 통합 문서. 통합 진행의 최종 동의는 전역 관리자만 가능하며, 설정이 다르면 "Align org-wide app settings"에서 어느 쪽 값을 쓸지 고릅니다.

7. 가용성(Available) vs 설치(Installs)

항목의미통합 시 동기화관찰
가용성 (Available to)누가 찾아서 설치·사용할 수 있나. "Built for your org" 표시 기준✔ 사용자 지정 동기화 대상 문서MAC "특정 사용자" ↔ TAC "Everyone"으로 표시되는 불일치 관찰 → 동기화 오류 추정 실측 추정
설치·고정 (Installs, 설정 정책)사용자에게 미리 설치하고 사이드바에 고정✘ 동기화 목록에 없음TAC에서 별도 설정 필요 → TAC 관리자에게 따로 요청 실측
💡 Teams 스토어 "Built for your org"에 보이는 것은 가용성으로 정해집니다(허용된 사용자가 찾을 수 있음). 설치(Installs)는 찾지 않아도 자동으로 깔리고 고정되게 하는 별도 단계입니다. MAC 게시 마법사에도 "설치 가능 대상"과 "미리 설치 대상(선택)"이 따로 있습니다.

가용성·설치 변경은 최대 24시간, 드물게 최대 6일 걸릴 수 있습니다. 그 이후에도 MAC·TAC 값이 다르면 지원 요청 대상입니다. 확인할 때는 지정하지 않은 사용자 계정으로 Teams 스토어를 검색해 보세요.

8. 용어: 앱 패키지 · Teams SDK · Agents SDK · Agents Toolkit

조직 카탈로그에 올릴 때 에이전트를 "감싸는" 것은 SDK가 아니라 앱 패키지(manifest.json + 아이콘을 묶은 zip)입니다. 실행은 계속 Copilot Studio가 맡습니다.

이름무엇인가언제 쓰나
앱 패키지 / 앱 매니페스트배포 단위(zip)모든 경로의 마지막 단계. Copilot Studio는 자동 생성
Teams SDK (구 Teams AI Library)Teams용 에이전트·앱을 코드로 만드는 라이브러리직접 호스팅하는 사용자 지정 엔진 에이전트
Microsoft 365 Agents SDK여러 채널용 에이전트를 코드로 만드는 프레임워크 (Bot Framework 후속)Teams·Copilot·웹 등 다채널
Microsoft 365 Agents Toolkit (구 Teams Toolkit)개발·배포 도구 (VS Code 확장, atk CLI)atk package로 zip 생성, atk publish로 관리 센터 제출(관리자 승인 필요)

"리소스를 따로 둔 앱 배포"는 SDK로 코드를 짜고 Azure Bot·App Service 같은 리소스를 직접 둔 뒤 Agents Toolkit으로 패키징·제출하는 프로 코드 경로입니다. MAC에는 플랫폼이 "TeamsToolKit"으로, Copilot Studio 에이전트는 "Copilot Studio"로 표시됩니다.

9. 문제 해결 체크리스트 — "MAC에서 승인했는데 Teams에 안 보여요"

  1. 채널: CS 채널에 Teams가 켜져 있나? (MAC 요청 목록의 채널 필터로도 확인)
  2. MAC 승인: Requests에서 Publish to store 완료, 설치 가능 대상 지정
  3. TAC 목록: Manage apps 상단 Pending approval 위젯, 필터 해제 후 이름·앱 ID로 검색
  4. 통합 여부: "Move to unified app management" 버튼이 있으면 비통합 → TAC에서도 Publish (이중 승인)
  5. 목록에 안 보이면: 공유 링크나 매니페스트 id(A)로 앱 ID를 찾아 TAC 앱 상세로 직접 진입
  6. TAC 설정: ①(기본 가용성)·②(미리 보기) 상태 확인 — ①은 승인과 무관, 게시 후 기본 사용 범위만 결정
  7. 가용성 일치: MAC 대상 ↔ TAC Users and groups 비교, 지정하지 않은 사용자로 테스트
  8. 설치·고정: 필요하면 TAC 관리자에게 Installs·설정 정책을 따로 요청
  9. 대기: 최대 24시간(드물게 6일). Teams 클라이언트를 완전히 종료 후 재확인
  10. 그래도 불일치: 앱 ID·타이틀 ID·시점을 정리해 지원 요청
